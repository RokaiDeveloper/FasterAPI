# Política de Segurança

[English](SECURITY.md)

## Versões suportadas

As correções de segurança são avaliadas em relação à versão mais recente
publicada do FasterAPI. Versões antigas podem não receber correções. Atualize
para a versão compatível mais recente antes de relatar um problema.

## Relatando uma vulnerabilidade

Não relate suspeitas de vulnerabilidade por meio de Issues, Discussions ou Pull
Requests públicos.

Use o recurso privado de relatório de vulnerabilidades do GitHub:

**Security → Advisories → Report a vulnerability**

Se o relatório privado não estiver disponível, entre em contato com o
mantenedor do repositório pelo método de contato privado listado no perfil do
mantenedor no GitHub e não inclua informações sensíveis em uma issue pública.

Inclua:

- versão do FasterAPI afetada;
- versões do Java, Spring Boot e banco de dados;
- impacto e cenário de ataque;
- passos para reproduzir;
- uma prova de conceito mínima, quando for seguro;
- mitigação ou correção sugerida, se conhecida.

Não inclua credenciais reais, tokens de acesso, chaves privadas, dados pessoais
ou dados de produção. Substitua-os por valores sintéticos.

## Processo de divulgação

Os relatórios são analisados em privado. O mantenedor pode solicitar detalhes
adicionais, coordenar uma correção e publicar um aviso de segurança depois que
uma correção ou mitigação estiver disponível. Não há prazo garantido de
resposta ou correção.

Os relatórios e as correções de segurança continuam sujeitos à
[FasterAPI Proprietary Free-Use License](LICENSE).
